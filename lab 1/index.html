Experiment 01

Comparison of Virtual Machines & Containers

Deploying Ubuntu and Nginx Web Server across Vagrant/VirtualBox VMs and WSL/Docker Containers

Software & Hardware Requirements

  • Hardware: 64-bit System with Intel VT-x / AMD-V / Apple Silicon virtualization support, 8 GB RAM.
  • Windows Host: Oracle VirtualBox, HashiCorp Vagrant, WSL 2 (Ubuntu 22.04 LTS), Docker Engine.
  • macOS Host (Apple Silicon): Homebrew, QEMU (`qemu-system-aarch64`), `vagrant-qemu` plugin, Docker Desktop.

Theory & Architecture

Virtual Machines emulate a complete physical computer including Guest OS kernel on top of a Hypervisor. Containers virtualize at the OS kernel level using Linux Namespaces and Control Groups (cgroups), sharing the host kernel for maximum efficiency.

️ Experiment Setup – Part A: Virtual Machine (Windows/Linux)

Initialize and boot an Ubuntu 22.04 VM using Vagrant and VirtualBox, deploy Nginx, and observe metrics.

Vagrant VM Provisioning

Resource Utilization Observation

Parameter Virtual Machine (Vagrant/VirtualBox) Container (Docker Engine/WSL) Winner
Boot Time 25.4 seconds 0.8 seconds Container
Idle RAM Usage 1024 MB (Pre-allocated) ~32 MB (Dynamic) Container
CPU Overhead Higher (~5% hypervisor) Minimal (< 0.1%) Container
Disk Footprint ~3.5 GB (Virtual Disk) ~140 MB (Layered Image) Container
Isolation Security Strong (Hardware Boundary) Moderate (Kernel Namespace) VM

Result & Conclusion

The experiment confirms that containers deliver sub-second startup times and 10x-50x lighter memory utilization compared to virtual machines, making them ideal for microservices and cloud deployments.
